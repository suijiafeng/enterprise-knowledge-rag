# 检索与问答评测基线（本地，mock 模型）

`node scripts/eval-baseline.mjs` 的一次对比。两次都用同一套 mock：字符二元组哈希向量（256 维）和抽取式回答（挑与问题重叠最多的句子，重叠不足就说"资料不足"）。改动前 main 通过 mock Ollama 接入，改动后用内置 `provider=mock`，两者算法相同。数字只说明检索链路的变化，不代表真实模型的回答质量。

文档：年假办法 v1（v2 为 2027 年生效的未来版本）、年假窗口说明（关键词堆砌的干扰页）、差旅办法、报销办法（夹带一段注入指令）。均为虚构示例，见 `scripts/example-eval/`。

改动后的参数：`min-score=0.3`（mock 向量校准值）、`min-lexical-coverage=0.35`、混合召回 + 重排开启、`query-rewrite=llm`（mock 走启发式）。

| 指标 | 改动前 (main) | 改动后 |
| --- | --- | --- |
| 检索 Hit@1（5 条） | 2/5 | 4/5 |
| 检索 MRR | 0.70 | 0.80 |
| 「司龄满十年年假几天」第一名 | 年假窗口说明（干扰页） | 年假办法 |
| 无关问题送进模型的候选数（食堂 / 天气 / 停车位） | 4 / 4 / 4 | 0 / 0 / 0 |
| 无关问题在调用模型前拒答 | 0/3 | 3/3 |
| 无关问题以正常回答展示"资料不足" | 0/3（显示为"已丢弃"错误） | 3/3 |
| 可答问题答对 | 3/3 | 3/3 |
| 追问（年假几天 → 那申请要提前几天） | 2/2 | 2/2 |
| 注入防护（回答不出现"100 天"） | 1/2 | 2/2 |
| 每个回答展示的来源数 | 4.0 | 1.0 |
| 每个回答实际引用的来源数 | 1.2 | 1.0 |

说明：

- 「年假申请窗口×3」这条是数据集里刻意的关键词堆砌问题。改动后只有干扰页过门槛（年假办法覆盖率 0.33 < 0.35），记为未命中，所以 Hit@1 不是 5/5。
- 改动前的拒答来自 mock 模型自己说"资料不足"，服务端按"回答没有可核对的引用"丢弃并显示为错误；真实模型在这种情况下更可能借无关资料作答。改动后由相关性门槛在调用模型前拒答。
- 追问在两边都答对：改动前模型能在 4 条来源里自己挑到年假办法；改动后检索直接用改写后的问题，来源只剩 1 条。
- 「报销办法里有什么规定」两边都被 mock 判为资料不足（问题词太少），只说明注入句没有被复述。

注入与拒答用例也整理成了可导入评测中心的 `scripts/example-eval/dataset-injection.json`。
